# 知成：登录与用户权限设计 v0.1

日期：2026-10-19。状态：设计稿，尚未实现。

本文是后续开发方案，其中的登录接口、角色和权限规则均不属于当前版本已交付功能。
当前运行方式、功能和限制以 [README](../README.md) 与 [架构说明](架构说明-v0.1.md) 为准。

## 1. 第一版范围

采用 **账号密码登录 + 服务端登录会话 + 两种固定角色**，适配现有 FastAPI、MongoDB 和同源 HTML/JavaScript 页面。

- 管理员创建账号，用户登录、修改密码、退出登录；忘记密码由管理员重置。
- 全站课程、题库和已发布资料供所有已登录用户共享，聊天记录按用户隔离。
- 用户管理支持创建、查询、修改昵称和角色、启用/禁用、重置密码；删除账号用禁用代替。
- 第一版不做自助注册、短信/邮箱验证、第三方登录、自定义角色、菜单权限配置、班级或课程单独授权。
- 复用 MongoDB 保存登录状态；暂不引入 Redis、JWT 或独立认证服务。

这里的共享是产品规则。如果以后需要“不同学员只能访问各自购买的课程”，应另加课程授权，并同步约束检索、引用和原件下载。

## 2. 两种角色与数据范围

用户只有一个 `role`：`admin`（管理员）或 `user`（普通用户），角色及对应规则定义在代码中。

| 能力 | 普通用户 | 管理员 |
| --- | --- | --- |
| 浏览课程、章节、练习，主动查看答案 | 允许 | 允许 |
| 提问、流式问答、查看引用 | 允许 | 允许 |
| 下载已发布资料原件 | 允许 | 允许 |
| 创建、查看、继续、删除聊天 | 仅自己的 | 仅自己的 |
| 创建课程、导入/更新/删除资料、修改归属 | 不允许 | 允许 |
| 查看文档管理列表、导入任务、重试/删除任务 | 不允许 | 允许 |
| 用户列表、创建账号、设置角色、禁用、重置密码 | 不允许 | 允许 |
| 修改自己的密码 | 允许 | 允许 |

管理员角色不提供查看其他用户聊天的应用接口。数据库运维权限不属于这里的角色控制范围。

普通用户下载原件时，只能访问未删除文档的 `active_version`，且版本状态必须为 `ready`；显式传入其他版本也要校验。历史引用保留片段快照，引用版本已非当前版本时提示该版本原件不可下载。管理员可以查看未删除的其他版本。

## 3. 登录模块

### 3.1 使用流程

1. 页面启动先请求 `GET /api/v1/auth/me`；未登录时展示登录页。
2. 用户提交用户名和密码；校验成功后，服务端创建登录会话并写入 Cookie。
3. 后续请求由浏览器自动携带 Cookie，后端解析出当前用户。
4. 登录有效期固定为 8 小时，到期重新登录；第一版不做“记住我”和自动续期。
5. 退出时删除当前登录会话并清除 Cookie；改密、重置密码后，之前的所有登录会话失效。

登录会话集合命名为 `auth_sessions`，现有聊天仍使用 `sessions`，两者用途分开。

### 3.2 账号规则

- 用户名：3～32 位 ASCII 字母、数字、下划线；统一转小写后存储，创建后不修改。
- 昵称：1～50 个字符，可修改；不参与身份识别和权限判断。
- 密码：15～128 个字符，允许空格和 Unicode，不静默裁剪；不强制大小写、数字、符号组合。
- 密码使用 `pwdlib[argon2]` 的 Argon2id 哈希，盐由库生成；参数至少满足 OWASP 基线，部署时再测算耗时。
- 管理员创建或重置账号时设置临时密码，标记 `must_change_password=true`；通过线下渠道交付，不在列表中返回密码。
- 使用临时密码登录后，只允许查看自身登录状态、改密和退出；改密成功清除标记并重新登录。
- 用户不存在、密码错误、账号禁用统一提示“账号或密码错误”；按规范化用户名及来源 IP 分别限流，起始值为每账号 5 次失败/15 分钟、每 IP 30 次失败/15 分钟，超过返回 429。

限流第一版可使用当前单进程内存中的有界计数器并定期清理；重启会清空。后续增加多 worker 时再改成共享计数。只信任已配置反向代理提供的客户端 IP。

### 3.3 登录凭据与请求校验

- 使用密码学安全随机数生成至少 32 字节的不透明 token；Cookie 保存原值，MongoDB 仅存 token 的 SHA-256 摘要。密码仍使用 Argon2id。
- Cookie：`zhichengapp_auth`，`HttpOnly`、`SameSite=Lax`、`Path=/`，不设置 `Domain`；有效期与服务端一致。通过 HTTPS 部署时必须启用 `Secure`；本机 HTTP 开发显式关闭。
- 所有 POST/PATCH/PUT/DELETE 请求，包括登录、上传和流式问答，必须携带自定义头 `X-ZhiChengApp-Request: 1`；浏览器有 `Origin` 时必须与配置的应用源完全匹配，拒绝 `null`，不开放第三方跨域凭据访问。利用自定义头需要预检的浏览器机制防范 CSRF，不能只依赖 SameSite。
- CLI 同样发送自定义头，可以不带 `Origin`；页面统一请求封装和直接调用 `fetch` 的 SSE 路径都要覆盖。
- 每次请求检查 token、过期时间、账号状态及 `auth_version`，角色从当前用户记录读取。MongoDB 不可用时拒绝业务访问。
- MongoDB TTL 索引用于清理过期登录记录；接口仍显式判断过期，不能等待后台清理完成。
- 密码、Cookie、token 不写日志，也不存入 `localStorage`；用户与登录状态响应设置 `Cache-Control: no-store`。

注销、禁用、过期和角色变化对后续请求生效。已通过校验的 SSE 请求允许结束；本版不做后台主动断开连接。

## 4. 用户与权限模块

### 4.1 用户管理页面

增加一个仅管理员可见的“用户管理”入口：列表显示用户名、昵称、角色、状态、创建时间和最近登录时间，支持分页和按用户名/昵称搜索。

行操作为编辑、启用/禁用、重置密码；新建弹窗只填用户名、昵称、角色和临时密码。页面右上角显示当前用户、修改密码、退出登录。

第一版禁止管理员在页面/API 中修改自己的角色或禁用自己，也不提供批量操作，避免误操作导致无人管理。首次管理员由本地脚本交互创建，密码隐藏输入；脚本发现已有管理员时不再执行首次创建，不提供默认密码。

### 4.2 后端校验位置

在 `api/dependencies.py` 增加 `current_user`、`require_admin` 两个依赖：

- `current_user`：检查登录与账号状态；临时密码账号只放行 `/auth/me`、`/auth/password`、`/auth/logout`。
- `require_admin`：在 `current_user` 基础上要求 `role=admin`。
- 会话相关服务接收后端取得的用户 ID，以 `{id: session_id, user_id: current_user.id}` 查询。读取消息、继续问答、删除记录前都先核对归属，且应先于占用会话和读取历史。
- `user_id`、角色、状态均不能由普通业务请求指定或覆盖。前端隐藏入口只用于交互，后端负责授权。
- 未登录/失效返回 401；已登录但角色不足或必须改密返回 403；访问其他用户的聊天与访问不存在聊天统一返回 404。

所有业务 API 默认需要登录，包括 `/api/v1/capabilities`、原件下载及两个问答接口。匿名只开放登录页、静态资源、登录接口和最小化的 `/health/live`；`/health/ready` 及详细运行状态仅管理员可读，现有检查脚本同步适配。启用多用户部署时关闭公开的 `/docs`、`/redoc`、`/openapi.json`。

## 5. 最小数据模型

继续使用 `zhichengapp` 数据库，只新增两个集合，不建立角色表和权限表。

| 集合 | 字段 |
| --- | --- |
| `users` | `id`、`username`、`display_name`、`password_hash`、`role`、`status`（active/disabled）、`must_change_password`、`auth_version`、`created_at`、`updated_at`、`last_login_at` |
| `auth_sessions` | `id`、`token_hash`、`user_id`、`auth_version`、`created_at`、`expires_at` |
| 现有 `sessions` | 新增必填 `user_id`，由服务端写入 |

`users.username`、`auth_sessions.token_hash` 建唯一索引；`auth_sessions.expires_at` 使用 UTC 日期和 TTL 索引；为 `auth_sessions.user_id`、`sessions(user_id, created_at)` 建索引。将两个新集合加入现有 repository 白名单和初始化流程。

`auth_version` 初始为 1，登录时复制到登录会话；改密、重置密码、角色调整及账号状态变化时，在更新用户记录的同一原子操作中递增。每次鉴权比较版本，旧会话即使未及时删除也不能恢复使用。

`messages` 保持通过 `session_id` 归属聊天，先校验父会话再读写，避免重复存储用户字段。对外响应使用专门的用户 DTO，只返回基本资料；不直接返回包含密码哈希的数据库记录。

## 6. 新增接口

下表均位于 `/api/v1`。登录相关接口不接收客户端传入的用户角色。

| 方法与路径 | 权限 | 内容 |
| --- | --- | --- |
| `POST /auth/login` | 匿名 | 用户名、密码登录，写 Cookie，返回用户基本资料 |
| `GET /auth/me` | 已登录，含待改密账号 | 当前用户和是否必须改密 |
| `POST /auth/logout` | 可幂等调用 | 注销当前登录，清 Cookie；凭据已失效也返回 204 |
| `POST /auth/password` | 已登录，含待改密账号 | 校验旧密码、设置新密码，使全部旧登录失效 |
| `GET /users` | 管理员 | 分页、搜索用户 |
| `POST /users` | 管理员 | 创建账号，角色默认 `user`，用户名冲突返回 409 |
| `PATCH /users/{user_id}` | 管理员 | 只允许修改昵称、角色、状态；用户名不可变 |
| `POST /users/{user_id}/reset-password` | 管理员 | 设置临时密码、要求改密，使旧登录失效 |

现有接口不改路径，按第 2 节补充依赖和数据归属条件。现有练习列表继续不返回答案，用户主动请求解析时读取答案。

## 7. 接入现有项目

| 位置 | 计划变更 |
| --- | --- |
| `api/auth_service.py`、`api/user_service.py` | 新增登录与用户管理路由 |
| `schemas/auth.py`、`services/auth.py`、`services/users.py` | 请求/响应模型、登录校验、密码和用户管理用例 |
| `api/dependencies.py`、`app.py` | 认证/管理员依赖、路由注册、默认保护和写请求校验 |
| `repositories/mongo.py` | 新集合、索引、按用户查询会话的方法和用户原子更新 |
| `api/session_service.py`、`services/query.py` | 创建时写归属；列出、读消息、删除、普通/流式问答都校验本人 |
| 课程、题库、文档、任务 API | 根据权限矩阵保护；普通用户下载只允许当前活动版本 |
| `page/` | 登录/改密界面、用户管理面板、当前账号、请求头和 401 统一处理 |
| `scripts/` | 首次管理员创建、旧聊天归属迁移；CLI 导入、远程检查和评测脚本适配认证 |

CLI 使用同一个 HTTP 客户端先登录再操作，复用 Cookie；用户名作为参数，密码用隐藏输入，不放在命令行。已配置可信 HTTPS 地址时也可远程使用。

旧数据迁移：先备份，再创建首个管理员；将原本没有 `user_id` 的聊天显式归属该管理员，消息通过父会话继承归属。迁移前展示待处理数量并支持 dry-run，允许重复执行且不覆盖已有归属。无归属聊天默认不可访问，不兜底返回全量数据。

多用户启用后不保留匿名业务访问开关。前端收到 401 时中止当前流、清空内存中的聊天状态并展示登录页，避免切换账号后继续展示上一人的聊天。

## 8. 实现时的验收重点

1. 正确密码可登录；错误、过期、注销及禁用后的凭据不能访问业务接口。
2. 普通用户直接请求管理接口返回 403；伪造角色/用户 ID 无效。
3. A 无法列出、读取、继续提问或删除 B 的聊天，包括普通和 SSE 问答；拒绝时没有消息写入或会话占用副作用。
4. 修改/重置密码、改角色、禁用后，旧登录会话从下一次请求起失效；临时密码必须先改。
5. 未登录不能下载原件；普通用户不能下载构建中、失败或非活动版本；删除资料仍按原有规则拒绝下载。
6. 缺少自定义头或来源不合法的写请求被拒绝；登录、上传、SSE、CLI 的正常请求均可使用。
7. 两个账号先后使用同一浏览器，不串历史；旧聊天仅迁移到指定管理员，未迁移记录不外泄。
