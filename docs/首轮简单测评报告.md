# 知成 RAG 首轮简单测评

日期：2026-10-20。项目：`D:\code_workspace\ZhiChengApp`。

结论：现有真实检索与生成链路已跑通，12 道基础题全部达到本轮预期；另核实了 DOCX 数学公式入库丢失的问题。当前结果不能代表复杂问题或整体业务准确率。

## 核实的实现

- Markdown 使用 markdown-it 的 CommonMark 标题解析；DOCX 使用段落/表格与标题样式解析。
- 切分保留标题和位置；当前配置 target=512、max=768、overlap=64，按 embedding tokenizer 计数。
- BGE-M3 稠密与学习型稀疏向量，通过 Milvus 的 RRF 融合召回；稀疏向量不是 BM25。
- 实际 QueryService 检索候选数配置为 20，不足时扩大到 60；代码最多取 30 个候选重排，最终取 5 个。
- 生成前最多补充两个小父章节；上下文预算为 4000 个 embedding tokenizer token。这不是生成模型的精确 token 计数。
- 生成输出检查引用编号和活动版本，证据不足时返回 insufficient_evidence。
- MongoDB、Milvus、MinIO 实测 ready；真实本地模型在 cuda:0 上加载成功。
- 当前数据库共 11 份资料、2234 个章节、3607 个切片；本轮范围为活动版本的讲义，不包含题库和项目资料问答。

## 方法和范围

从已读的原文预先设定 10 道可回答题和 2 道无答案题，覆盖 Python、MySQL、Pandas、机器学习、深度学习五份讲义。题目、答案关键点和标准章节均在运行前保存。属于 AI 编写并核对的小样本冒烟集，无独立人工审核。

直接执行生产 QueryService / LangGraph 的 route → retrieve → generate，使用配置中的真实 embedding、reranker、Milvus、MongoDB 和 LLM。没有启用应用任务消费者，没有创建会话、导入资料或写入业务数据库。所有讲义活动版本在运行前后保持一致。

采用非流式、顺序、单次运行；本地模型先预热。耗时包含路由、检索、上下文构建和生成，不包含 HTTP/SSE、浏览器显示、模型加载或并发排队。模型加载另耗时 18.49 秒。未验证线上 HTTP 服务。

## 已确认的问题与建议

1. **优先补齐 DOCX 数学公式解析。** 读取 MinIO 原件确认：《机器学习》梯度下降章节的原始第 476 块存在 oMath 公式，但 Paragraph.text 为空；第 477 块存在四个 oMath 节点，入库文字缺失对应数学符号。当前 `utils/parsers/docx.py:81` 只取 `block.text`。应支持 OMML 转换，或显式标识不支持公式并选择已有识别路径，然后重新导入受影响资料。此问题不因概念题通过而消失；本轮没有给公式题打分。
2. **继续保留独立的回答与引用核对。** `services/query.py:495` 附近主要验证模型 supported 自报、编号和版本，不能单独证明语义正确。本轮新增的逐题 AI 核对记录在 review.json。
3. **下一轮扩到 30～50 题。** 增加公式、代码、表格、跨章节、多证据与相近概念干扰题，再考虑优化模型或召回参数。现有检索对比脚本与生产候选扩大、截断路径不完全一致，正式比较应复用生产检索逻辑。

## 限制与复现

- 无独立人工标注、无封闭测试集；题目来自已知讲义并偏基础，可能高估真实用户问题的表现。
- 仅每题单次运行；无置信区间结论，无负载测试，无完整 API/SSE 和多轮对话评测。
- 无答案样本只有两题，不能推断普遍拒答能力；其初始标签采用讲义范围与缺失标记检查，并非穷尽语义证明。
- 不报告未采集的 token 成本和首字延迟；不得用关键词命中率冒充正确率。
- raw-report.json 是程序原始数据，其中语义指标保留 null；review.json 记录额外 AI 核对；final-report.json 汇总两者并保留评分来源。
- rag_smoke_eval.py 中的种子题绑定本轮文档与章节编号。后续资料更换后需重新审核标签，不能直接沿用本轮分数。
